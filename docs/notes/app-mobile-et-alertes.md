# App iPhone / Android, alertes et application installable

Notes détaillées de Sillage, sorties de CLAUDE.md le 23/11/2026 (texte d'origine, non résumé). Voir CLAUDE.md pour les règles générales.

## Alertes météo et application installable (essai du 25/10/2026, en ligne le 26/10/2026)
- Application installable : `manifest-test.webmanifest` (lié par test.html : `start_url` / `id` `./test.html`, nom « Plan My Ride · test ») et `manifest.webmanifest` (pour index.html : `./index.html`) ; icônes `icons/` (icon-192, icon-512 aussi « maskable », apple-touch-icon 180, badge-96 monochrome), générées par script (tracé blanc départ vert / arrivée orange, traits de vent jaunes sur fond `--accent`). Balises `theme-color`, `apple-mobile-web-app-capable`. **Mise en ligne** : en recopiant test.html dans index.html, remplacer `manifest-test.webmanifest` par `manifest.webmanifest`.
- `sw.js` (racine, portée `./`) : seulement `push` (notification : titre, texte, icône, badge, `tag`, `data.url`) et `notificationclick` (ouvre ou réutilise la page et y navigue vers `data.url`, même origine seulement). Aucun cache ni `fetch` : la page reste toujours celle du site. Enregistré au premier « Activer » ; `r.update()` au chargement si déjà enregistré.
- Page Moi, carte « Alertes météo » (`#alCard`, `AL`, `alLoad` / `alRender` / `alSave`, appelées par `meOpen`) : « Activer sur cet appareil » (`#alOn` : `Notification.requestPermission`, `sw.js`, clé VAPID de la fonction (`key`), `pushManager.subscribe`, `subscribe` à la fonction ; réabonnement si la clé a changé), dossier puis parcours (test.html, 13/11/2026, demande d'Antoine : choix `#alKind` Sortie / Commute / Ultra au style `.me-mseg`, avec le nombre de parcours de chaque dossier, `AL.kind` = dossier du parcours de l'alerte à l'ouverture, sinon Sortie ; `#alRoute` ne liste que ce dossier, avec « Choisis un parcours… » quand le parcours de l'alerte n'en fait pas partie ; changer de dossier n'enregistre rien, et `alSave` garde le parcours enregistré tant qu'aucun n'est choisi ; parcours du compte seulement : `LIB.list` `remote`), départ (`#alTime`, par défaut l'heure de la page Sortie), « Prévenir » (`#alWhen` : la veille à 20 h `eve` / le matin à 7 h `morn`), jours de sortie (`#alDays`, ISO 1 = lundi), « Envoyer l'alerte maintenant » (`#alTest`, action `test`), « Couper les alertes » (`#alOff` : `enabled = false` + désabonnement de l'appareil). Réglages écrits à chaque changement dans `push_alerts` (une ligne par compte, RLS : la sienne) avec vitesse / VAM de la page Sortie (`meGet('ride')`), fuseau du navigateur et page d'origine (`page`, pour le lien). Sans prise en charge : message `#alWhy` (sur iPhone hors app installée : « Partager → Sur l'écran d'accueil », iOS 16.4+), notifications bloquées : idem.
- Lien d'une alerte : `?route=ID&date=AAAA-MM-JJ&time=HH:MM` (lu tout au début du script : `pmr-last-route`, `sessionStorage` `pmr-ride-date` / `pmr-ride-time` lus par `initInputs`, paramètres retirés de l'adresse) → ce parcours en page Sortie à ce jour et cette heure.
- Serveur : fonction edge `push-alerts` (source `supabase/functions/push-alerts` : `index.ts`, `webpush.ts` = Web Push sans dépendance, VAPID ES256 + chiffrement aes128gcm RFC 8291 en Web Crypto, vérifié contre `http_ece` ; `forecast.ts` = prévision du parcours ; déployée sans vérification JWT, elle authentifie elle-même) : actions `key`, `subscribe`, `unsubscribe`, `test` (jeton de session, compte actif + `pmr`) et `cron` (en-tête `x-cron-token` = `push_keys.cron_token`). Clés VAPID créées au premier appel et gardées dans `push_keys` (RLS sans politique : clé de service seulement ; jamais dans le dépôt). Tables `push_subs` (appareils ; 404 / 410 → supprimé, 5 échecs de suite → supprimé par `push_sub_fail`) et `push_alerts`. Tâche pg_cron `pmr-push-alerts` (`2 * * * *`, pg_net) : à l'heure locale 20 h (`eve`, pour le lendemain) ou 7 h (`morn`, pour le jour même), une fois par jour (`last_sent`), si le jour est coché. Prévision : parcours `routes.pts`, 13 points au plus, Open-Meteo AROME jusqu'à J+2 (sinon modèle par défaut), vitesse + VAM sans vent, pluie / vent de face / rafales / ressenti, mêmes seuils que la page (`GUST_WARN` 50, `GUST_DANGER` 70), meilleure heure de 6 h à 17 h si nettement meilleure. Notification : « Demain 09:00 · Boucle » / « 🟠 Au sec, mais rafales à 58 km/h · ressenti 9 °C · arrivée vers 11:42 » / « Mieux à 14:00 (…) ».
- Limites : pas de widget d'écran d'accueil en version web (il faudra l'app des stores) ; sur iPhone, notifications seulement depuis l'app installée sur l'écran d'accueil.

## App iPhone / Android (dossier `app/`, depuis le 26/10/2026)
- Projet Capacitor 8 (`app/`, décrit dans `app/README.md`) : identifiant **`cc.sillage.app`** (définitif une fois publiée), nom « Sillage », version 0.1.0. Pages **embarquées** (pas de chargement du site en ligne) : `npm run build` reconstruit `app/www` depuis `index.html` (`--test` / `npm run sync:test` : depuis `test.html`) ; `www/` n'est pas versionné. Projets natifs `app/android` et `app/ios` versionnés ; clés de signature et fichiers Firebase / APNs jamais dans le dépôt (`app/.gitignore`).
- `app/scripts/build-www.mjs` adapte la copie sans toucher la page web, et s'arrête (« introuvable ») si un des textes attendus a changé : insère `native.js` avant tout script, fige la balise viewport (`minimum-scale=1,maximum-scale=1,user-scalable=no` : sinon iOS élargit la zone d'affichage dès qu'un élément dépasse), retire le manifeste, polices Archivo / IBM Plex Mono (@fontsource, latin + latin étendu) et Leaflet 1.9.4 en local (`vendor/`), `redirectTo` de « Mot de passe oublié ? » = `window.SILLAGE_WEB` (`native.js`, https://app.sillage-ride.eu/index.html ; `WEB` du script = https://app.sillage-ride.eu/, depuis e561022 ; page web : le lien de l'e-mail ne peut pas revenir dans l'app), liens Admin vers le site. **Si on modifie dans index.html / test.html une de ces lignes (balise viewport, manifeste, Google Fonts, Leaflet CDN, `redirectTo`, lien Admin), adapter le script.** suncalc / opening_hours restent chargés à la demande depuis jsDelivr.
- `app/native/native.js` (seulement dans l'app, `window.Capacitor.Plugins`) : `html.native` / `html.native-ios|android`, `window.SILLAGE_NATIVE` ; `navigator.share({ files })` et `<a download href="blob:">.click()` → fichier écrit dans le cache (Filesystem) puis feuille de partage (Share) ; bouton retour Android : ferme le dernier `dialog[open]`, sinon Échap si carte plein écran / `sheet-open` / `lib-open`, sinon `minimizeApp` ; `appUrlOpen` recharge la page avec les paramètres du lien (`?route=…`, `?invite=…`) ; style de la barre d'état selon `data-theme` / thème de l'appareil.
- Origine de l'app : `https://app.sillage-ride.eu` (Android) / `capacitor://app.sillage-ride.eu` (iPhone), fixée par `server.hostname` : ne plus la changer (localStorage, IndexedDB et session Supabase en dépendent). Les fonctions edge répondent `Access-Control-Allow-Origin: *`. `track()` écrit dans `pmr_visits` depuis Android (http(s), pas localhost) mais pas depuis l'iPhone (protocole `capacitor:`) ; `activity_log` marche partout.
- Icônes et écran de démarrage : `app/scripts/make-icon-sources.mjs` (même dessin que `icons/sillage-512.png`, en vectoriel) → `app/assets/`, puis `npm run icons` (@capacitor/assets, Android + iOS seulement).
- Écran de démarrage animé (06/11/2026, demande d'Antoine, sur le modèle d'UltraRide) : iOS impose un écran de lancement fixe, donc `native.js` pose par-dessus la page un bloc `.app-splash` (fond `#14201b`, logo « nuage roulant » avec la roue — anneau + rayons — qui tourne en 2,4 s et les trois gouttes qui tombent en boucle, 1,6 s décalées de 0,5 s ; « Sillage.cc » en Archivo 800 sous le logo, bloc centré en hauteur ; en bas « POWERED BY » en blanc + logo Beyond The Track `app/native/btt-logo.png`, copié dans `www/` par `build-www.mjs`), 3 s puis fondu de 300 ms et retrait. Pas d'animation si mouvements réduits (appareil ou `html[data-motion="reduce"]`). L'écran de connexion masque tout le `<body>` sauf lui (`body.gated > :not(.gate){display:none!important}`) : `native.js` ajoute `html.native body.gated>.app-splash{display:block!important}` (spécificité plus forte), sinon l'écran de démarrage n'apparaissait qu'une fois connecté·e (bug du 06/11/2026). Raccord avec l'écran natif : `capacitor.config.json` `launchAutoHide: false`, `launchFadeOutDuration: 0` ; `SplashScreen.hide({ fadeOutDuration: 0 })` après le chargement du logo BTT et deux `requestAnimationFrame`, et de toute façon après 1,5 s ; `assets/splash.png` (`make-icon-sources.mjs`) = le logo seul à la même place (760 px centré à 1366, 1290 sur 2732, « aspect fill » : 1 px d'image = 100vmax ÷ 2732 → CSS `27.8vmax` à `calc(50% − 2.8vmax)`), même fond en clair et en sombre (`--splashBackgroundColorDark '#14201b'`) ; le nom et le crédit arrivent en fondu, donc l'écran natif n'a que le logo. Pour tester : supprimer l'app du téléphone avant de réinstaller (iOS garde l'ancien écran de lancement). Maquette : artifact « Écran de démarrage Sillage ».
- Bandeau rouge de diagnostic `overflowCheck` (`native.js`, élément `#sillageDbg`, toutes les 3 s) : signale l'élément le plus large qui dépasse l'écran sans être coupé par un parent qui tient dans l'écran (06/11/2026 : on remonte tous les parents, pas seulement le plus proche — le `<svg>` des tracés Leaflet, plus large que la carte par construction, déclenchait un faux « Trop large : 438 px / écran 430 px » sur la Carte des points). ## Notifications natives (Firebase) — 25/11/2026
- Projet Firebase « Sillage » (`sillage-9d06c`), apps `cc.sillage.app` Android + iOS. Plugin `@capacitor-firebase/messaging`. Les fichiers `google-services.json` (`app/android/app/`) et `GoogleService-Info.plist` (`app/ios/App/App/`, ajouté à la cible App dans Xcode) ne sont jamais commités (`app/.gitignore`).
- Alertes personnelles → un jeton FCM par appareil, table `push_devices` (`supabase/sql/2026-11-25_push_devices.sql`, RLS sans politique). `push-alerts` envoie aux abonnements Web Push ET aux jetons FCM (`fcm.ts`, HTTP v1, secret `FCM_SERVICE_ACCOUNT` = JSON du compte de service). Actions `device_register` / `device_unregister`. Jeton supprimé si FCM répond 404/400 ou après 5 échecs.
- Client (`alNat()` dans test.html) : dans l'app, `alOn` demande la permission, récupère le jeton et l'enregistre ; le jeton est ré-enregistré à chaque ouverture si l'alerte est active. Toucher la notification ouvre son `url` (`native.js`).
- iOS : `FirebaseApp.configure()`, transmission du jeton APNs, `aps-environment` (development ; Xcode le passe en production à l'archivage), `UIBackgroundModes` remote-notification. Clé APNs .p8 à téléverser dans Firebase › Cloud Messaging.
