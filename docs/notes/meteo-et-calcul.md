# Météo, architecture du script et modèle de vitesse

Notes détaillées de Sillage, sorties de CLAUDE.md le 23/11/2026 (texte d'origine, non résumé). Voir CLAUDE.md pour les règles générales.

## Architecture du script (dans `index.html`)
- `parseGPX` → `prepare` (distances cumulées, altitude lissée, D+/D− avec seuil 3 m, cap sur ~150 m)
- Import sans filtre d'extension (07/11/2026, index.html et test.html) : `#file` et `#tafFile` n'ont plus d'attribut `accept` (un GPX nommé « trace.gpx (2) », reçu par WhatsApp ou sans extension était grisé ou refusé par le sélecteur du téléphone ; cas d'un testeur avec un export COROS). C'est `parseGPX` qui juge le contenu (retire un BOM et les espaces avant `<?xml`, sinon « Ce fichier n'est pas un GPX lisible. ») ; le nom de secours (fichier sans `<name>`) retire `.gpx` et un « (2) » final.
- `makeSamples` : jusqu'à ~60 points d'échantillonnage pour la météo
- Météo (`getWeather(src, from, to, today)`), source au choix dans le menu déroulant « Source météo » (`#wxSrcSel`, depuis le 14/10/2026, `localStorage` `pmr-wxsrc`, `WX_SRC` / `WX_KEYS`) : meteoblue (`mb`), AROME (`arome`), MET Norway (`met`), Open-Meteo (`om`). Par défaut meteoblue si connecté, sinon AROME. En public, meteoblue s'affiche « 🔒 meteoblue » : le choisir remet la source d'avant et ouvre le message `#wxLock` (version d'essai, débloqué plus tard contre un forfait payant ; bouton `#wxLockOk`). Horizon par source `WX_DAYS` (mb 7, arome 4, met 9 jours) : au-delà, Open-Meteo prend le relais (`S.wxAlt`, `S.wxUsed` = `src+om`) ; départ au-delà de l'horizon (`fallback: 'horizon'`) ou échec (`'error'`, note) → Open-Meteo. Crédits `WX_LINK` / `WX_TXT` / `wxParts`.
  - Autres modèles nationaux (essai du 25/10/2026, en ligne le même jour) : groupe « Autres modèles nationaux » du menu, servis gratuitement par Open-Meteo (CC BY 4.0) comme AROME. Table `OM_MODELS` (clé → `name`, `models` = identifiants essayés dans l'ordre par `fetchOMModel` : un identifiant refusé par Open-Meteo, message « invalid / model », passe au suivant ; `days` = horizon ; `org` / `url` / `mdl` pour les crédits `WX_TXT` / `WX_LINK` ; `hint` pour `#wxSrcHint`) : `arome` (meteofrance_seamless, 4 j), `icon` (dwd_icon_seamless puis icon_seamless, 7 j), `ch` (meteoswiss_icon_seamless, 5 j), `it` (italia_meteo_arpae_icon_2i, 3 j), `knmi` (knmi_seamless, 10 j), `dmi` (dmi_seamless, 10 j), `ukmo` (ukmo_seamless, 7 j), `ecmwf` (ecmwf_ifs puis ecmwf_ifs025, 15 j) ; groupe « Amérique du Nord » (essai du 25/10/2026, en ligne le même jour) : `gfs` (ncep_gfs_seamless puis gfs_seamless : HRRR 3 km sur les États-Unis puis GFS, 16 j), `nbm` (ncep_nbm_conus, 11 j, `prob: true` : seul modèle imposé qui garde `precipitation_probability`, via `OM_PROB` dans `fetchOM`), `gem` (gem_seamless puis cmc_gem_seamless : HRDPS, RDPS puis GEM mondial, 10 j). `WX_SRC` / `WX_DAYS` en sont tirés. Hors de la zone d'un modèle régional (valeurs vides) : `omGaps` détecte les trous, `omFill(wx, alt)` les comble point par point et heure par heure avec Open-Meteo automatique (`used` = `src+om`, `S.wxInfo.outside` = part des points complétés, rappelée dans l'indication « ⚠ 50 % du parcours hors de la zone de ce modèle »). Identifiants relevés dans la documentation d'Open-Meteo le 25/10/2026, pas vérifiés en direct (le conteneur n'atteint pas l'API) : un identifiant faux fait passer sur Open-Meteo avec la note d'erreur habituelle. Noms des sources aussi dans `WX_NAME` / `WX_SHORT` de admin.html et admin-test.html.
  - Ajouts du 26/10/2026 (sur test.html ; identifiants vérifiés en direct sur l'API Open-Meteo ce jour-là, depuis le navigateur d'Antoine) : Europe `geo` (geosphere_seamless : AROME Autriche puis ECMWF, 15 j), `chmi` (chmi_aladin_seamless : ALADIN Europe centrale puis ECMWF, 15 j) ; Amérique du Nord `nam` (ncep_nam_conus, 3 j) ; groupe « Asie » `jma` (jma_seamless : MSM puis GSM, 11 j), `cma` (cma_grapes_global, 5 j) ; groupe « Modèles d'intelligence artificielle » `aifs` (ecmwf_aifs025_single, 15 j) et `aigfs` (ncep_aigfs025, 16 j), avec `fill: true` : rafales, ressenti, ensoleillement manquants toujours complétés par `omFill` (condition `OM_MODELS[src].fill || omGaps`). Écartés (identifiants acceptés mais séries vides le 26/10/2026) : kma_seamless, bom_access_global, gfs_graphcast025. Rappel licence : l'API gratuite d'Open-Meteo est réservée à l'usage non commercial (moins de 10 000 appels par jour) ; une app payante sur les stores demandera un abonnement Open-Meteo ou un serveur Open-Meteo à soi.
  - Source « 📍 Le plus précis selon le lieu » (`loc`, essai du 26/10/2026 sur test.html) : **source par défaut** de tout le monde (`wxSrc()` rend `loc` sans choix enregistré ; avant : meteoblue si connecté, sinon AROME ; meteoblue reste au choix). `locKey(lat, lon)` : zones approximatives, des plus petites aux plus grandes — Corse et France (+ Barcelone, Luxembourg, Bruxelles, Turin, Alpes françaises, Genève) `arome` ; Suisse, Bâle, Mulhouse `ch` ; Autriche hors Bavière `geo` ; Tchéquie `chmi` ; Italie, Slovénie `it` ; Royaume-Uni, Irlande `ukmo` ; Pays-Bas `knmi` ; Islande `dmi` ; Scandinavie, Danemark, pays baltes `met` ; reste de l'Europe (Allemagne, Espagne, Portugal, Balkans, Turquie…) `icon` ; Japon `jma` ; Canada `gem` ; États-Unis (avec Alaska, Hawaï) `gfs` ; partout ailleurs `ecmwf`. `locPick(points, départ, aujourd'hui)` : zone de la majorité des points ; départ au-delà de l'horizon de ce modèle → `ecmwf` (15 j), puis `om`. Dans `run` : `src` = choix résolu (clé du cache, `getWeather`, crédits) et `S.wxPick` ; `renderWxSrc` garde `loc` dans le menu et préfixe l'indication « 📍 Pour ce parcours : AROME (Météo-France). … ». Mes sorties (`outFetch`) : même choix par parcours (`locModel` : identifiant Open-Meteo, `metno_seamless` pour MET Norway) au lieu d'AROME partout, trous comblés par Open-Meteo automatique (`omGaps` / `omFill`). Les alertes (`push-alerts`) restent sur AROME jusqu'à J+2.
  - Recherche du 26/10/2026 d'autres modèles gratuits : rien de régional en Amérique latine, Afrique, Moyen-Orient ni Océanie chez Open-Meteo (BOM et KMA sans données ce jour-là). Hors Open-Meteo : Google WeatherNext 2 (API Ensemble d'Open-Meteo, pas de 6 h, conditions de Google à vérifier), WRF 4 km du service argentin (fichiers bruts sur AWS, demanderait un relais serveur), SMHI (Scandinavie, déjà couverte par MET Norway), api.weather.gov (États-Unis, déjà couvert par NBM / HRRR). Pas intégrés.
  - `fetchOM(from, to, model)` : un seul appel Open-Meteo multi-points (16 jours), `timeformat=unixtime`, `timezone=GMT`, 40 s au plus (sinon « Météo indisponible », horaires calculés sans météo). `model` = `AROME_MODEL` (`meteofrance_seamless` : AROME France ~2 jours puis ARPEGE, 4 jours) pour la source AROME, sans `precipitation_probability` (variable absente : série NaN).
  - `fetchMET` : MET Norway, `api.met.no/weatherapi/locationforecast/2.0/complete` (≈ 9 jours ; horaire sur 2–3 jours puis pas de 6 h). Depuis le 14/10/2026, passe par la fonction edge `met-norway` (`metRelay`, source `supabase/functions/met-norway`, clé anon, JWT vérifié ; 40 points au plus par appel) : User-Agent `Sillage/1.0 (https://app.sillage-ride.eu/; hello@sillage-ride.eu)` (le même pour `osm-import` et `osm-overpass`), cache partagé entre visiteurs dans la table `met_cache` (RLS sans politique, clé de service seulement ; clé `lat,lon,alt` à 3 décimales et altitude au 10 m, pas de nouvelle demande avant Expires, puis If-Modified-Since ; 4 demandes à la fois, arrêt sur 429 → la page affiche « MET Norway limite les demandes » ; réponse allégée de même forme que met.no ; ménage des lignes de plus de 3 jours). Si la fonction ne répond pas (hors 429), appels directs depuis le navigateur (`metPoint`, `MET_PAR` = 3 à la fois). Points : un tous les `MET_KM` (10) km, au plus `MET_MAX` (40), coordonnées à 3 décimales et altitude au 10 m (mêmes clés que le cache partagé), cache `localStorage` `pmr-met-pts` jusqu'à Expires (1 h au moins). `metCompact` : séries horaires (instant interpolé, vent m/s → km/h par composantes, pluie et symbole de `next_1_hours` sinon `next_6_hours` ÷ 6 rangés à la fin de l'heure, symbole → code WMO `metCode` / `MET_SYM`, ressenti par la formule de Steadman, jour/nuit par `sunRiseSet`, soleil ≈ (1 − nébulosité) en journée, rafales quand présentes) ; points d'échantillonnage interpolés par `mbSample`.
  - `fetchMB` : fonction Supabase `meteoblue` (source `supabase/functions/meteoblue`, clé `METEOBLUE_API_KEY` côté serveur, réservée aux comptes actifs avec l'accès Plan My Ride, quota `quota_mb` par mois, vent converti en km/h, au plus 10 points par appel, `debug: true` renvoie la réponse brute et l'en-tête `mb-credits-accounted`). Compte meteoblue en essai gratuit : seuls les paquets d'essai sont permis (basic-1h, wind-3h, clouds-3h…, pas de wind-1h / clouds-1h). Crédits par point : basic-1h 8 000, + clouds-3h 16 000, + wind-3h + clouds-3h 32 000, quelle que soit la durée → le client demande `MB_PKG` = `basic-1h_clouds-3h` (essai depuis le 13/10/2026, 16 000 crédits par point, `MB_CREDITS`) et 7 jours. Pas de rafales dans le paquet : depuis le 25/10/2026, `getWeather` les reprend d'Open-Meteo aux mêmes points et aux mêmes heures (`gustFill`, un appel Open-Meteo de plus, gratuit ; `r.gustOm` → texte « rafales d'Open-Meteo » sous le menu) ; affichage des rafales masqué si `gust` reste NaN (`st.hasGust`) ; nébulosité (`totalcloudcover`) et ensoleillement (`sunshinetime`) du paquet clouds-3h, interpolés sur l'heure par la fonction ; à défaut déduits du pictogramme horaire (`MB_CC`, `MB_SUN`). Code WMO (icône, libellé) toujours via `MB_PICTO`. Couverture nuageuse affichée dans les infobulles du profil et des flèches. Pour revenir à basic-1h : `MB_PKG`, `MB_CREDITS`, et changer `MB_CACHE`.
  - Un point tous les `MB_KM` (20) km, au plus `MB_MAX` (8), avec l'altitude GPX (`asl`) ; cache par point (`localStorage` `pmr-mb-pts2`, clé lat/lon à 3 décimales + altitude, 2 h, 40 points) : changer l'heure, la date ou recharger la page ne coûte rien ; demandes identiques en cours partagées (`MB_PENDING`). Chaque point d'échantillonnage est interpolé entre ses deux voisins (`mbSample` : vent par composantes, ciel/jour du plus proche, température corrigée de −6,5 °C/km selon l'altitude).
  - Consommation (`#wxUse`, `renderWxUse`) : sous le choix de source, crédits de ce chargement (`credits` renvoyé par la fonction, en-tête `mb-credits-accounted`) et « Solde : reste / total crédits » avec une fine barre. Le reste vient de l'action `usage` de la fonction (API Accounting de meteoblue `/account/usage`, somme de `request_credits` ; forfait `METEOBLUE_QUOTA`, 10 M par défaut), lue au plus toutes les 10 min et 1,5 s après chaque nouvel appel (`mbUsageRefresh`, `localStorage` `pmr-mb-usage`).
  - meteoblue couvre 7 jours à partir d'aujourd'hui : au-delà, Open-Meteo prend le relais (`S.wxAlt`, `wxAt` essaie `S.wx` puis `S.wxAlt`) ; départ au-delà de 7 jours ou échec de meteoblue → Open-Meteo (`S.wxFallback` 'horizon' / 'error', note d'état en cas d'erreur). `renderWxSrc` : indication sous le choix (points, run du modèle) et crédit du pied de page (`#wxCredit`) ; `wxCreditTxt` pour l'export image.
- Graphes du jour / des trajets (`drawDayWx`) : une valeur par demi-heure plus toujours un point à l'arrivée (`ptAdd(tb)`, corrigé le 26/10/2026 sur test.html : la courbe de température d'un trajet de vélotaf de 50 min s'arrêtait à 30 min).

En haut, les heures puis une ligne de pictogrammes du ciel puis une ligne de flèches de vent (sens où il va, couleur `windStrength`, `WARROW`) tous les quarts d'heure (`drawSky`, 16 px, au moins 19 px d'écart sinon on en saute ; position au km atteint à cette heure).

## Modèle de vitesse
- montée : temps = distance / vitesse plat + D+ / VAM
- descente (pente < −1 %) : vitesse × (1 + (pente − 1 %) × 6), plafonné à ×1,35
- vent : facteur 1 − 0,012 × composante de face (km/h), borné [0,55 ; 1,35]

## Open-Meteo payant (abonnement « API Standard » depuis le 29/10/2026 ; en ligne le même jour dans test.html, index.html, admin-test.html et admin.html)
- Abonnement de l'association : licence commerciale + 1 million d'appels par mois (29 € HT / mois). Clé dans le secret Supabase `OPENMETEO_API_KEY`, jamais dans le dépôt ni dans la page ; hôte payant `customer-api.open-meteo.com` (même syntaxe que l'API gratuite + `&apikey=`).
- Fonction edge `open-meteo` (source `supabase/functions/open-meteo`, JWT vérifié + rôle `authenticated` exigé : la clé publique seule est refusée) : `POST { q }` = chaîne de requête de `/v1/forecast` (format contrôlé, `apikey` interdit) → réponse d'Open-Meteo telle quelle, en-tête `x-om: hit | miss` (exposé en CORS). Cache partagé `om_cache` (SHA-256 de `q`, 30 min ; purgé par `purge_old_data`) ; compteur par jour `om_usage` (demandes, réponses du cache, appels décomptés estimés comme Open-Meteo : par lieu, max(1, variables / 10) × max(1, jours / 14) ; lecture admins) via `om_count`. `{ ping: true }` vérifie la clé.
- Page (test.html) : `omFetch(url, ms)` juste après `AROME_MODEL` ; avec un compte connecté, passe par le relais (jeton de session de `sbIfLogged`), sinon ou si le relais ne répond pas lui-même (pas d'en-tête `x-om`), API gratuite en direct. Utilisée par `fetchOM` (tous les modèles, Mes sorties, rafales, compléments `omFill`) et `flowGrid` (vent animé). Essai réel du relais le 29/10/2026 (clé acceptée, cache, refus de la clé publique) et essai Playwright (2 appels par le relais, aucun direct).
- Alertes : `push-alerts/forecast.ts` utilise `customer-api` avec la clé quand elle existe (sinon l'API gratuite). Redéployée le 29/10/2026 (version 6, import npm: au lieu de jsr:).
